# Техническая документация Block Juggle (Python/Pygame)

## 1. Обзор архитектуры

Проект реализован на языке Python с использованием библиотеки Pygame (рекомендуется `pygame-ce`). Архитектура следует упрощенному принципу разделения ответственности (MVC-лайт), где данные отсоединены от логики рендеринга, но классы объектов управляют своим состоянием.

Проект разбит на 4 модуля:
1.  **`settings.py`**: Глобальные константы, конфигурация и статические данные.
2.  **`board.py`**: Класс `Board`, управляющий состоянием игровой сетки 8x8.
3.  **`shape.py`**: Класс `Shape`, описывающий перетаскиваемые фигуры и их анимации.
4.  **`main.py`**: Точка входа, системные функции, обработка событий и оркестрация игрового цикла.

---

## 2. Обзор модулей и классов

### 2.1. Модуль `settings.py` (Конфигурация)

Хранит статические данные, не изменяющиеся во время выполнения.

*   **Константы экрана**: `WIDTH`, `HEIGHT`, `FPS`.
*   **Константы сетки**: `GRID_SIZE` (8), `CELL_SIZE` (50px).
*   **Смещения (Offsets)**: `GRID_OFFSET_X`, `GRID_OFFSET_Y` используются для центрирования сетки на экране. Сетка рисуется не от координат (0,0), а от этих смещений.
*   **`SHAPES_DATA`**: Список списков (матриц). `1` обозначает наличие блока, `0` — пустоту.
    *   *Техническая деталь:* Фигуры задаются минимально возможными прямоугольными матрицами (например, линия 4x1 — это `[[1, 1, 1, 1]]`, а L-форма — `[[1,0], [1,0], [1,1]]`). Это важно для корректного расчета хитбоксов и привязки к сетке.

### 2.2. Модуль `board.py` (Класс `Board`)

Управляет логикой игрового поля.

#### Ключевые поля:
*   **`self.grid`**: Матрица 8x8.
    *   `0`: Ячейка пуста.
    *   `pygame.Surface`: Ячейка занята, хранится ссылка на текстуру блока (для отрисовки). *Ранее хранились цвета, теперь — поверхности.*
*   **`self.animating_blocks`**: Список словарей, хранящий данные о блоках, находящихся в процессе анимации исчезновения (при очистке линий).

#### Ключевые методы:
*   **`update(self)`**: Вызывается каждый кадр. Уменьшает поле `scale` у блоков в `self.animating_blocks`. Когда `scale <= 0`, блок удаляется из списка.
*   **`draw(self, surface)`**: Двухпроходный рендеринг:
    1.  Рисует пустую сетку (фон ячеек и линии обводки) на основе констант смещения.
    2.  Рисует статические блоки из `self.grid`.
    3.  Рисует анимированные (исчезающие) блоки из `self.animating_blocks`, центрируя их внутри ячейки по мере уменьшения масштаба.
*   **`can_place(self, shape_matrix, grid_x, grid_y)`**: Алгоритм коллизий. Проверяет, не выходят ли блоки фигуры за границы 8x8 и не накладываются ли они на уже занятые ячейки в `self.grid`.
*   **`place(self, shape_matrix, texture, grid_x, grid_y)`**: Фиксирует фигуру на поле. Записывает ссылку на `texture` в соответствующие ячейки `self.grid`. Начисляет базовые очки (1 очко за блок). Вызывает `check_lines`.
*   **`check_lines(self)`**: **Ядро логики.**
    1.  Сканирует строки и столбцы. Использует `all()`, чтобы проверить, что все ячейки не равны `0`.
    2.  Собирает координаты заполненных ячеек в `set()` (чтобы избежать дублирования на пересечениях).
    3.  Для каждой ячейки: создает запись в `self.animating_blocks` (копирует текстуру, задает `scale=1.0`), затем обнуляет ячейку в `self.grid`.
    4.  Начисляет бонусные очки (+10 за каждую очищенную линию).

### 2.3. Модуль `shape.py` (Класс `Shape`)

Управляет фигурами в нижней зоне и их Drag & Drop логикой. Использует технику **Lerp (Linear Interpolation)** для всех анимаций движения и масштабирования.

#### Ключевые поля:
*   **`self.matrix`**: Ссылка на матрицу из `SHAPES_DATA`.
*   **`self.texture`**: Загруженный `pygame.Surface` блока.
*   **Координаты**:
    *   `self.start_pos`: Изначальная точка в "кармане" внизу.
    *   `self.x, self.y`: Текущие экранные координаты.
    *   `self.target_x, self.target_y`: Точка, куда фигура стремится прилететь (используется для плавного возврата).
*   **Масштаб**:
    *   `self.scale`: Текущий масштаб (0.0 - 1.0).
    *   `self.target_scale`: Целевой масштаб (0.6 когда лежит внизу, 1.0 когда перетаскивается).

#### Ключевые методы:
*   **`update(self)`**: **Heartbeat анимаций.** Вычисляет промежуточные значения координат и масштаба, приближая их к `target` значениям на определенный коэффициент (0.25 для движения, 0.15 для масштаба) каждый кадр. Это создает эффект плавного замедления (easing out). Сбрасывает масштаб в 0.0 при создании (эффект появления).
*   **`draw(self, surface)`**: **Критический участок рендеринга.** Исправляет проблему "щелей" между блоками при масштабировании.
    1.  Рассчитывает `cell_size` как `CELL_SIZE * self.scale`.
    2.  **Двухпроходная отрисовка фигуры:**
        *   Пасс 1: Проходит по матрице и рисует **все** тени.
        *   Пасс 2: Проходит по матрице и рисует **все** текстуры блоков поверх теней.
        *   *Почему это важно:* Если рисовать "тень-блок, тень-блок", тень второго блока наложится на текстуру первого. Разделение пассов гарантирует, что тени никогда не перекроют блоки.
    3.  Использует `math.ceil` для размера ячейки при масштабировании, чтобы избежать субпиксельных пустот.
*   **`snap_to_grid(self, board)`**: Вызывается при отпускании мыши.
    1.  Конвертирует экранные `self.x, self.y` в координаты сетки `grid_x, grid_y` с помощью `round()`, учитывая смещения поля.
    2.  Вызывает `board.can_place`. Если `True` -> вызывает `board.place` и возвращает `True` (фигура уничтожается в `main`).
    3.  Если `False` -> устанавливает `self.target_x, self.target_y` в `self.start_pos`. Фигура плавно улетает назад в следующем цикле `update`.

### 2.4. Модуль `main.py` (Система)

Отвечает за инициализацию, загрузку ресурсов, высокоуровневое состояние игры и рендеринг UI.

#### Системные функции (вне класса):
*   **Загрузка ресурсов (`load_block_image`, `load_background` и т.д.)**: Обязательно используют `.convert_alpha()` для PNG (с прозрачностью) или `.convert()` для JPG (фон без прозрачности) для оптимизации Blit-операций. Масштабируют изображения под `CELL_SIZE` или размер экрана превентивно. Реализуют fallback-логику (создание `pygame.Surface` залитого цветом), если файл ассета не найден.
*   **Сохранение счета (`get_high_score`, `save_high_score`)**: Простой I/O с текстовым файлом `highscore.txt`.
*   **`check_game_over(board, shapes)`**: Алгоритм проверки конца игры. Полный перебор: берет каждую фигуру из `active_shapes` и пытается "примерить" её ко всем ячейкам поля 8x8 через `board.can_place`. Если ни одна фигура не лезет ни в одну дырку — Game Over.

#### Функция `main()` (Игровой цикл):
*   **Состояние `game_over`**: Булевая переменная, переключающая режим обработки событий и отрисовки.
*   **Анимация проигрыша**: Переменная `go_anim_progress` (0.0 -> 1.0). Использует кубическое сглаживание (`ease_t = 1 - (1 - t)**3`) для расчета `alpha` канала затемнения фона и вертикального смещения (`slide_y`) элементов меню "Game Over".
*   **Дерево рендеринга (Z-order)**:
    1.  Фон.
    2.  Объекты игры (`board.draw`, `shapes.draw`). *Рисуются всегда, даже в Game Over, находясь под полупрозрачным оверлеем.*
    3.  Интерфейс игры (счет, рекорд, кнопка рестарта).
    4.  **Если Game Over:** Полупрозрачный оверлей (SRCALPHA Surface) -> Текст Game Over -> Результаты -> Кнопка Play. Все элементы Game Over меню рендерятся с учетом `alpha` и `slide_y` из анимационного таймера.

## 3. Ключевые технические решения

1.  **Lerp-анимации (Плавность)**: Вместо жесткого присваивания координат (`x = target`), используется формула `x += (target - x) * friction`. Это создает органичное, плавное движение, зависящее от FPS. Применяется для движения фигур, изменения масштаба при захвате и появления фигур.
2.  **Матричная логика**: Все коллизии и размещения вычисляются на уровне целочисленных матриц (индексы 0-7), а не экранных пикселей. Пиксели используются только для рендеринга и Drag & Drop ввода.
3.  **Оптимизация рендеринга**:
    *   Преобразование Surface (`convert_alpha`) при загрузке.
    *   Пре-масштабирование текстур (не масштабировать 50x50 блок внутри цикла draw, если он статический).
    *   Двухпроходная отрисовка в `Shape` для корректного наложения теней.
4.  **Сохранение текстур в сетке**: Поле `board.grid` хранит ссылки на объекты текстур (`pygame.Surface`). Это позволяет легко рисовать поле в `board.draw`, просто блиттая то, что лежит в ячейке, не зная, какого оно цвета.
5.  **Кубическое сглаживание (Easing) для UI**: Формула `1-(1-t)**3` (ease-out cubic) применяется к анимации Game Over, делая выезд меню быстрым в начале и плавно замедляющимся в конце, что приятнее глазу, чем линейное движение.
